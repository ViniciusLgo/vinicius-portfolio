For a long time, I worked behind the scenes.

I started my career in IT infrastructure — support, networking, servers, corporate environments. That's where I learned to understand technology end-to-end, even before writing my first line of production code.

## What infra teaches that code alone doesn't

When you work with infrastructure, you learn that a system doesn't end at `git push`. It has to run somewhere, be monitored, survive restarts, and deal with permissions, logs, and network failures.

That perspective changed how I write code. I think about the runtime environment from the very start.

## Debugging as investigation

Knowing how to read logs before touching code is a skill I brought from infra. Debugging isn't guesswork — it's investigation. Check services, analyze traces, test one variable at a time.

## Conclusion

If you're starting out in IT and you're in infra today, don't see it as a detour. It's a solid foundation for becoming a developer who understands where software actually lives.
